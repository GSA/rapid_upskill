# Your first prompt

This walkthrough takes about 15 minutes. You will add a practice prompt, preview and write its page, run the checker, and read the result. Then you will remove the practice files. Nothing is sent to an AI model.

## Before you start

- Install Python 3.10 or newer.
- Clone the repository and open a terminal at its root. Run every command there.
- Skim the [Prompt file format](authoring-conventions.md#prompt-file-format) section if you want the reasons behind each field.

## Step 1: Create the prompt file

Create the file `prompts/op/first-prompt-practice.md`. Create the `op` folder first if it does not exist. Paste in this content.

{% raw %}

~~~~~markdown
---
id: "P-OP-99"
title: "First prompt practice"
stage: "OP"
purpose: "Practice adding a prompt."
placeholders: ["TOPIC", "AUDIENCE"]
capabilities: ["llm"]
---
````text
Explain {{TOPIC}} to {{AUDIENCE}} in three short sentences.
Define any term that the audience might not know.
````

This prompt exists only for the walkthrough. Delete it when you finish.
~~~~~

{% endraw %}

The fields work like this.

- `id` is `P` for prompt, `OP` for operating practices, and `99`, a number chosen for practice.
- `stage` is `OP`. It matches the ID and the folder name `op`.
- `placeholders` lists the two names that the prompt uses. `capabilities` lists what the prompt needs from a platform.
- The four-backtick fence holds the prompt. The text after it is notes.

## Step 2: Preview with a dry run

```bash
python3 scripts/site/sync.py
```

This prints a plan and writes nothing. Look for the page it would create for your prompt, `docs/prompts/op/p-op-99.md`. On a first run, the plan may also list index pages. If the plan reports a problem with your file, fix the line it names.

## Step 3: Write the generated page

```bash
python3 scripts/site/sync.py --write
```

Run the same command a second time. The second run should change nothing.

## Step 4: Run the checker

```bash
python3 scripts/site/check.py
```

Each finding is one line: `path:line RULE message`. Look for lines that name your prompt or its generated page. Fix the source file, run `sync.py --write` again, and then run the checker again. The command exits with status 1 if it finds any error.

If you skipped Step 3, expect a finding from rule R11, because the generated page is missing.

## Step 5: Read the generated page

Open `docs/prompts/op/p-op-99.md` in a text editor. Its title is the ID followed by the title. It holds a table of facts about the prompt, a Prompt section with your text, and a Notes section with the text after the fence. The sync tool fills "Used in" from pages that list the ID under `prompts:`. No page lists this prompt.

Do not edit this file. The sync tool owns it, and your edits would be reported as drift.

## Step 6: Clean up

1. Delete `prompts/op/first-prompt-practice.md`.
2. Run `python3 scripts/site/sync.py --write --prune`. It deletes the stale generated page for the practice prompt.
3. Run `python3 scripts/site/sync.py --check`. It exits with status 0 when nothing has drifted.

## Next steps

To add a real prompt, read [Authoring conventions](authoring-conventions.md) and pick an ID and a folder. List the ID under `prompts:` on the page that uses it, and link the generated page in that page's Prompts section. Then work through the [Release checklist](release-checklist.md).
