# Branches are just names

**What is a branch?**

A branch is a movable label attached to one commit. Creating one copies no files; it adds a second name for the commit you are standing on. Run `git branch feature`, then `git rev-parse main feature`, and both names print the same commit ID.

Many newcomers believe that a branch is a copy of the project folder. It is not. Your folder holds one set of files at a time, and `git switch feature` (Git 2.23 or later; older versions use `git checkout feature`) rewrites those files to match the commit that `feature` points to.

**What is HEAD?**

HEAD says where you are. Normally it holds the name of the current branch, and `git symbolic-ref HEAD` prints something like `refs/heads/main`. When you commit, the branch that HEAD names moves forward to the new commit, and HEAD follows.

If you check out a bare commit with `git switch --detach` followed by a commit ID, HEAD holds that ID instead, and `git status` reports "HEAD detached". Commits made in that state are on no branch. Git warns you if you switch away while such commits belong to no branch. Run `git switch -c rescue` first if you want to keep the work. In Git older than 2.23, `git checkout -b rescue` does the same job.

**How do I combine two branches?**

Switch to the branch that should receive the work, then run `git merge other-branch`. The branch you are on receives the work. The other one stays where it was.

Depending on the histories, Git by default finishes a merge in one of two ways, or does nothing when there is nothing to merge:

1. Fast-forward. If the receiving branch has no commits of its own since the two split apart, Git slides its label forward to the other branch's commit. No new commit is created and the history stays a straight line.
2. Merge commit. If both branches have new commits, Git combines the two sets of changes and records a new commit with two parents.

Options and settings can change the default: `git merge --no-ff`, or the setting `merge.ff=false`, makes a merge commit even when a fast-forward is possible.

A common mistake is to assume that merging must create a commit. By default, a fast-forward only moves a label, which is why the log shows no merge entry afterwards.

**Does merging delete the other branch?**

No. Both names exist after the merge. Remove a finished branch yourself with `git branch -d name`. Git normally refuses if the branch still holds commits that are not merged; `-D` overrides that refusal.

A common mistake is to think that deleting a branch deletes its work. Deleting a merged branch removes only the label. The commits stay in the history because the merged history still contains them.
