## Problem and context

This source addresses the objective-level question of what a branch and
HEAD are, and how a merge finishes. New team members often picture a
branch as a copy of the project folder and expect every merge to add a
new commit; this source explains why neither picture is right.

## Scope

Covered: a branch as a movable label on a commit; HEAD as the pointer to
the current commit or branch; the detached-HEAD state; the fast-forward
and merge-commit outcomes of a merge; deleting a merged branch. Not
covered: remote branches, merge conflicts, and rewriting history; other
admitted sources address those.

## Findings

- 0 new commits are created per fast-forward merge, dated 2026-02-03,
  labeled mechanism: "No new commit is created and the history stays a
  straight line."
- 2 parents are recorded per merge commit, dated 2026-02-03, labeled
  mechanism: "Git combines the two sets of changes and records a new
  commit with two parents."

## Normative statements

- Git refuses to delete a branch that still holds commits not yet
  merged, unless the `-D` flag overrides the refusal; this binds anyone
  running the delete command, not just the branch's own author.
- The branch you want to receive the merged work must be checked out
  before `git merge` is run; this binds the person doing the merge.

## Critical assessment

The source restates Git's own documented behavior rather than reporting
new research, so it is a repeater, not a primary source; a conflict of
interest is unlikely for the same reason. Its examples assume exactly
two branches; a history with three or more branches merging into one
target still resolves case by case the same way, but the source never
says so directly, which is a gap worth flagging rather than assuming.

## Relation to the seed

The seed held that merging two branches always creates a new commit that
records both parents. This source corrects that claim: a fast-forward
merge moves the branch label and creates no new commit at all, so a new,
two-parent commit only appears when both branches carry commits of their
own.
